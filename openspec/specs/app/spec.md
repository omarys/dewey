# App Specification

> Generated by openlore v1.2.0 on 2026-10-07 15:05

## Purpose

Manages core application state, coordinates library scanning, filtering, and navigation for series
and chapters.

## Requirements

> `src/app.rs`

### Requirement: InitializeApplication

The system SHALL the application must initialize configuration, database handle, event sender, and initial library state while initiating background scanning.

#### Scenario: SuccessfulApplicationInitialization
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** A valid configuration, connected database, and open event channel
- **WHEN** The new method is invoked
- **THEN** App instance SHALL be created, initial series and chapters loaded, and background library scan
initiated

### Requirement: SpawnBackgroundLibraryScan

The system SHALL the application shall spawn an asynchronous background thread to scan the library without blocking ui startup or user interaction.

#### Scenario: InitiateNonBlockingScan
- **GIVEN** The application is running and has access to the event sender
- **WHEN** spawn_background_scan is called
- **THEN** A detached thread SHALL execute scanner operations and dispatch completion events over event_tx

### Requirement: HandleScanCompletion

The system SHALL the application must update internal state and library notifications when a background scan completes.

#### Scenario: ProcessFinishedScanSummary
- **GIVEN** A background library scan completes and emits a ScanSummary
- **WHEN** on_scan_completed is called with the summary
- **THEN** Application state SHALL reflect scan outcomes and reload modified series data

### Requirement: ReloadSeries

The system SHALL the application shall reload series metadata and library contents from the persistent database into memory.

#### Scenario: RefreshSeriesList
- **GIVEN** Persistent series records in the database
- **WHEN** reload_series is executed
- **THEN** Internal series collection SHALL be repopulated with current records and filter states refreshed

### Requirement: ApplyFilter

The system SHALL the application must filter the active series collection based on current search tokens, categories, status, and filter modes.

#### Scenario: FilterSeriesBySearchQueryAndCategory
- **GIVEN** A loaded series list and active filter query tokens or category settings
- **WHEN** apply_filter is called
- **THEN** The visible series items SHALL contain only series matching all active filter criteria

> `src/debug_history.rs`

### Requirement: DefaultPath

The system SHALL resolves the standard filesystem location for the debug history file based on the user's home directory.

#### Scenario: StandardPathResolution
- **GIVEN** A configured HOME environment variable
- **WHEN** default_path is called
- **THEN** Returns the path pointing to ~/.local/state/dewey/debug_history.json

### Requirement: LoadHistory

The system SHALL reads and deserializes debug history entries from a specified file path.

#### Scenario: FileExistsWithValidJSON
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** An existing debug history JSON file
- **WHEN** load is called with the file path
- **THEN** Returns the parsed list of DebugHistoryEntry items

#### Scenario: FileMissingOrCorrupt
<!-- openlore-test: tags=regression (auto) -->
- **GIVEN** A non-existent or invalid JSON file path
- **WHEN** load is called
- **THEN** Returns an empty vector without raising an error

### Requirement: RecordHistory

The system SHALL appends or updates a recent reading entry, truncates list to max_entries, and persists changes to disk.

#### Scenario: RecordReadingProgress
<!-- openlore-test: tags=regression (auto) -->
- **GIVEN** A chapter read event and an existing history file
- **WHEN** record is called
- **THEN** Places the new entry at the top, eliminates duplicate path entries, truncates to MAX_ENTRIES, and
writes to disk

### Requirement: LoadOrFallback

The system SHALL loads history entries from file, or queries database read history if the file is empty and writes results back to file.

#### Scenario: FileContainsEntries
- **GIVEN** A populated debug history file
- **WHEN** load_or_fallback is called
- **THEN** Returns the entries directly without querying the database

#### Scenario: FileIsEmptyWithDatabaseEntriesAvailable
- **GIVEN** An empty or missing debug history file and available database records
- **WHEN** load_or_fallback is called
- **THEN** Retrieves recent history from the database, persists them to the file, and returns the entries

> `src/event.rs`

### Requirement: CreateEventHandler

The system SHALL initializes a new event handler channel and background listener task with the specified tick rate.

#### Scenario: InitializeHandler
- **GIVEN** A valid tick duration
- **WHEN** new is called
- **THEN** Spawns an asynchronous event listener task and returns the handler and sender channel

### Requirement: NextEvent

The system SHALL awaits and retrieves the next available application event from the receiver queue.

#### Scenario: EventReadyInChannel
- **GIVEN** Pending events in the receiver channel
- **WHEN** next is called
- **THEN** Returns Some(AppEvent) containing the next event

### Requirement: DrainInputEvents

The system SHALL discards transient user input events while preserving critical background task notifications.

#### Scenario: DrainWithMixedEvents
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** Receiver buffer containing Key, Tick, and DownloadSuccess events
- **WHEN** drain is called
- **THEN** Key and Tick events are discarded while DownloadSuccess is preserved in the queue

### Requirement: SuspendStream

The system SHALL aborts the background event reader task and drains user input to yield stdin to external child processes.

#### Scenario: SuspendForExternalProcess
- **GIVEN** An active event listener task
- **WHEN** suspend is called
- **THEN** The background task is aborted, pending user inputs are drained, and stdin is released

### Requirement: ResumeStream

The system SHALL restarts the background crossterm event stream and timer tick listener task.

#### Scenario: ResumeListening
- **GIVEN** A suspended or newly created EventHandler
- **WHEN** resume is called
- **THEN** Clears pending input and spawns a new task streaming crossterm events and ticks to the channel

> `src/scanner.rs`

### Requirement: ScanDirectory

The system SHALL scans the library directory, discovers series and chapters, records them in the database, and returns a scan summary.

#### Scenario: SuccessfulLibraryScan
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** A valid library directory containing series directories with chapters and an initialized database
- **WHEN** scan_directory is called with the database and library path
- **THEN** New and updated series and chapters are persisted to the database and a ScanSummary is returned

#### Scenario: LibraryDirectoryDoesNotExist
<!-- openlore-test: tags=regression (auto) -->
- **GIVEN** A path to a non-existent directory
- **WHEN** scan_directory is called
- **THEN** An error result is returned or scan terminates gracefully

### Requirement: CleanupStaleRecords

The system SHALL cleans up any database series or chapters that point to non-existent files or removed directories.

#### Scenario: StaleChaptersOrSeriesExist
<!-- openlore-test: tags=regression (auto) -->
- **GIVEN** Database records referencing files or folders that no longer exist on disk
- **WHEN** cleanup_stale_records is executed with currently discovered directories
- **THEN** The missing chapter file paths or records are deleted from the database and count of cleaned records
is returned

#### Scenario: NoStaleRecords
- **GIVEN** All database records correspond to existing files on disk
- **WHEN** cleanup_stale_records is executed
- **THEN** No records are deleted and 0 is returned

### Requirement: FindSeriesDirectories

The system SHALL recursively discovers candidate series directories under the root library directory.

#### Scenario: DiscoversSeriesSubdirectories
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** A root directory containing subdirectories with comic content
- **WHEN** find_series_directories is called
- **THEN** A sorted list of valid series directory paths is returned

### Requirement: IsLeafImageChapter

The system SHALL determines whether a directory represents a leaf image chapter folder without archives or series.json.

#### Scenario: DirectoryIsLeafImageChapter
- **GIVEN** A directory containing image files and no subdirectories or archive files
- **WHEN** is_leaf_image_chapter is checked
- **THEN** Returns true

#### Scenario: DirectoryContainsNestedSubdirectoriesOrArchives
- **GIVEN** A directory containing zip/cbz files or series.json
- **WHEN** is_leaf_image_chapter is checked
- **THEN** Returns false

### Requirement: IsChapterFile

The system SHALL checks whether a file path corresponds to a supported chapter file format.

#### Scenario: ValidChapterFileFormat
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** A file path ending with a supported archive extension such as .cbz or .zip
- **WHEN** is_chapter_file is invoked
- **THEN** Returns true

#### Scenario: UnsupportedFileFormat
- **GIVEN** A text file or non-comic file
- **WHEN** is_chapter_file is invoked
- **THEN** Returns false

### Requirement: HasChapterFiles

The system SHALL verifies whether a directory contains any valid comic chapter files.

#### Scenario: DirectoryContainsChapters
- **GIVEN** A folder with at least one comic file or leaf image folder
- **WHEN** has_chapter_files is called
- **THEN** Returns true

#### Scenario: EmptyOrNonComicDirectory
- **GIVEN** A directory with no chapter files
- **WHEN** has_chapter_files is called
- **THEN** Returns false

### Requirement: FindCoverImage

The system SHALL finds a cover image file located within a given series directory.

#### Scenario: CoverImageFound
- **GIVEN** A series directory containing cover image files (e.g. cover.jpg)
- **WHEN** find_cover_image is called
- **THEN** Returns Some(PathBuf) pointing to the cover image

#### Scenario: NoCoverImageFound
- **GIVEN** A series directory without matching image files
- **WHEN** find_cover_image is called
- **THEN** Returns None

### Requirement: FindCoverImageFromEntries

The system SHALL identifies a cover image candidate from an existing list of path entries.

#### Scenario: CoverExistsInEntryList
- **GIVEN** A slice of path entries containing a valid cover image file
- **WHEN** find_cover_image_from_entries is called
- **THEN** Returns Some(PathBuf) for the matching entry

### Requirement: ParseExplicitChapterNumber

The system SHALL attempts to extract an explicit chapter number prefix/pattern from a path.

#### Scenario: ExplicitChapterPrefixPresent
- **GIVEN** A filename containing 'Chapter 5' or 'Ch. 12'
- **WHEN** parse_explicit_chapter_number is called
- **THEN** Returns Some with the parsed float value

#### Scenario: NoExplicitChapterToken
<!-- openlore-test: priority=high (auto) -->
- **GIVEN** A filename without chapter or episode keywords
- **WHEN** parse_explicit_chapter_number is called
- **THEN** Returns None

### Requirement: ParseChapterNumber

The system SHALL parses chapter number using precompiled static regex heuristics across multiple formats.

#### Scenario: StandardChapterNumberParsing
- **GIVEN** A path with chapter numbering in brackets, delimiters, or pure numbers
- **WHEN** parse_chapter_number is called
- **THEN** Returns Some(f64) corresponding to the detected chapter number

### Requirement: DetectPageCount

The system SHALL detects the page count from .cbz/.zip archives or leaf chapter folders.

#### Scenario: ArchivePageCountDetection
- **GIVEN** A valid .cbz or .zip archive containing image files
- **WHEN** detect_page_count is called
- **THEN** Returns Some(i64) with the count of image files inside the archive

#### Scenario: FolderPageCountDetection
- **GIVEN** A directory containing page images
- **WHEN** detect_page_count is called
- **THEN** Returns Some(i64) with the count of image files inside the directory

> `src/terminal.rs`

### Requirement: CreateTerminal

The system SHALL initializes a new tui instance with a ratatui stdout crossterm backend.

#### Scenario: SuccessfulTerminalCreation
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** Standard output is available and accessible
- **WHEN** new is called
- **THEN** Returns a new Tui instance wrapping the Ratatui terminal

### Requirement: InitializeTerminal

The system SHALL enables raw mode, enters alternate screen, enables mouse capture, hides the cursor, and clears the terminal screen.

#### Scenario: InitializeTUIDisplayState
- **GIVEN** An uninitialized Tui instance
- **WHEN** init is called
- **THEN** Terminal raw mode is enabled, alternate screen is entered, and screen is cleared

### Requirement: RestoreTerminal

The system SHALL disables raw mode, leaves alternate screen, disables mouse capture, and restores cursor visibility to return terminal to default state.

#### Scenario: RestoreTerminalToOriginalState
- **GIVEN** A running or active TUI session
- **WHEN** restore is called
- **THEN** Raw mode is disabled, alternate screen exited, mouse capture turned off, and cursor restored

### Requirement: SuspendTerminal

The system SHALL temporarily suspends tui mode so an external gui or cli app can run without interference.

#### Scenario: SuspendTUIModeForExternalProcess
- **GIVEN** An active TUI session needing to launch an external command
- **WHEN** suspend is called
- **THEN** Raw mode is disabled and alternate screen is exited with cursor visible

### Requirement: FlushInput

The system SHALL flushes any pending input events from the terminal to prevent keystroke leakage.

#### Scenario: ClearPendingInputBuffer
- **GIVEN** Buffered keystrokes or queued crossterm events
- **WHEN** flush_input is called
- **THEN** Terminal input queue is flushed via libc tcflush and pending crossterm events are drained

### Requirement: ResumeTerminal

The system SHALL resumes tui mode after an external process completes by re-enabling raw mode, alternate screen, and flushing lingering inputs.

#### Scenario: ResumeTUIMode
- **GIVEN** A previously suspended Tui session
- **WHEN** resume is called
- **THEN** Raw mode and alternate screen are re-established, screen is cleared, and input queue is flushed

### Requirement: GetTerminalMut

The system SHALL provides a mutable reference to the underlying ratatui terminal instance.

#### Scenario: AccessMutableTerminal
<!-- openlore-test: priority=high (auto) -->
- **GIVEN** A Tui instance
- **WHEN** terminal_mut is called
- **THEN** Returns a mutable reference to the inner Ratatui Terminal for drawing
